# TrustMem-Bench evaluation card

TrustMem-Bench measures which pending requests change completion under a designated cross-session tool receipt intervention. The evaluator starts from a fixed opening and uses the upstream workflow's completion rule. It compares full request sets, charged tool operations and, when available, native confirmation.

The P3 diagnostic task gives a participant an observed removal run and the allowed organizer annotations. It asks the participant to forecast the directed set of changed requests under receipt restoration or an eligible single-fee change. The native continuations supply the labels. Acceptance requires a complete, schema-valid submission and reports exact target-set accuracy, class accuracy, coverage and incremental replay calls. Both changes and unchanged outcomes are scored. Multiple opening–controller cells share histories.

P4 adds a native tool-calling protocol on known openings. The tables distinguish upstream release status, working and failed interface configurations, stable keep and sham controls, and genuinely eligible single-fee cases. The archive and keep conditions expose different interfaces. Replay of recorded model actions tests execution and scoring. Re-running inference tests the reproducibility of the choices themselves.

The benchmark targets restorable simulators with shared execution budgets and stable tool-grading contracts. It supports within-opening intervention comparisons. Broad population estimates require additional workstreams beyond the fixed release. The raw logs, upstream input cache and frozen world snapshots are locally reconstructed or supplied under their respective terms.
