# Research positioning and publication gates

The core question remains: when does evidence retained from earlier sessions justify a changed action, what additional observations are needed, and does a durable revision support later use?

The following nearest neighbors constrain novelty claims:

- [AMV-Guard](https://arxiv.org/html/2610.31446v1), sections 3–5, already extracts action premises and selects verification under risk and cost. Action conditioning and a verification gate alone are not our novelty.
- [ReScopeBench](https://arxiv.org/html/2611.05450v1), sections 2–3 and appendices C.3.2/D.1, already studies experience lifecycles, pre-submission evidence, repeated queries and subsequent reuse. Adding cross-session execution alone does not establish an evaluation gap.
- [The Value of Memory in Language Agents](https://arxiv.org/html/2610.31303v1), sections 3.2 and 6.2, already specifies common access conditions, marginal memory interventions and multiple cost dimensions. A single writeback toggle or joint cost measurement is not a new principle.

The executable release is a development instrument. Its explicit source/coverage contracts, actual observation storage, separate numeric grader and ordinary references make future comparisons inspectable. These engineering properties are not by themselves a novel research contribution.

## Conditions for a paper claim

| Gate | Current state | Required evidence |
|---|---|---|
| Runnable environment | Implemented for documented algebraic mechanisms | Continue portability and third-party adapter checks. |
| Numerical reference | Separate raw parser plus SQL | Add independent semantic calibration for future native workflows. |
| Ordinary references | Eager/full and lazy/group references retained | Include equivalent ordinary automated extraction when claiming automatic premise recovery. |
| New evaluation knowledge | Not established | A reproducible finding changing a scientific judgment beyond existing lifecycle and verification studies. |
| Native diversity | Two archive producers, same count mechanism | Additional genuinely different native workflows, not only renamed fields or more seeds. |
| Held-out confirmation | Not established | Freeze implementations and source/history-level splits before outcomes. |
| New method | Not established | A concrete, important residual after fair ordinary methods and a demonstrated new computation. |
| Submission readiness | Not established | Complete comparative results, documented limitations, rights/licensing, and paper-to-evidence audit. |

Controlled tasks may deliberately target a causal question, but must retain sufficient controls, ordinary recovery, equivalent legal paths, all failures and actual costs. Benchmark design must not manufacture an author-method win by denying ordinary capabilities or adding artificial verification delay.
