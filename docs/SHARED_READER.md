# Common native-note reader contract

`trustmem_runtime.reader.run_session` accepts original retrieved notes, a reader
callback, current task/source, actual source tools and an optional native save
callback. No hidden reference or model client is part of this runtime.

All backends share query(group/full), calculate over complete JSON receipt
literals, source-free quality_check, save of an acquired observation, unchanged
submit and abstain. The normal new contract has four actions; historical two-action
results are unchanged. Explicit remaining actions and terminal requirements do
not mask actions or auto-submit. Free/tool-first modes only change instructions.

Each actual input/response and generated result is saved separately. A last-slot
tool result without a next invocation is generated, not delivered. Wrong integers
are committed without repair. `calculate` binds the computation to the task but
does not authenticate a native writer's content merely because it contains JSON
and a source ID. Semantic support must be separately graded against actual
observations; unparsed prose remains unknown.

The zero-API qualification used64 scripted deliveries across verbatim SQLite and
ordinary source-bound coverage summaries, with64 real fresh-process reads. A
separate optional pinned Mem0 run made6 correct scripted deliveries,6 native
fresh-process searches and6 scripted writer callbacks through actual infer=True
operations. These are plumbing controls on old fixtures, not model performance.

Ordinary complete/early materialization, legal archive recovery and lazy caching
must retain equal access before a system-performance comparison. Bootstrap and
recovery integration for the new common reader is still pending. The historical
unified runtime already includes these strong ordinary policies; they must not
be dropped to make a proposed memory mechanism look necessary.
