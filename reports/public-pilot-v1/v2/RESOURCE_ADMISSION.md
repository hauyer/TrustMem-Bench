# Before-model resource gate, separate from task correctness

2026-11-13 Asia/Shanghai. Addendum to the bounded public pilot; written before any model call. The v2 zero-API runs show the GH full-history input can exceed5.8MB. This motivates a small-batch transport/spending constraint, not a semantic method or a failed memory benchmark.

For every originally selected public history, compute the largest actually serialized reader input over both ordinary lazy/eager complete streams. A history enters the first paid batch only if that maximum is at most524,288 UTF-8 bytes. The rule is applied to the entire history and all memory/policy conditions together, never to particular failing tasks or a favorable backend. No source/table/note truncation, alternative dates, replacement sources or model-output selection.

The parent proposal has96 positions/12 streams on2 public histories. Report resource-ineligible histories and their planned positions explicitly. The eligible pilot may have fewer positions; its outputs cannot establish performance on excluded sources. Preflight source/task correctness is a qualification requirement, not the gate's ranking statistic. The gate reads input file sizes, not score labels. If no history qualifies, do not spend API money.

The original paid-admission record is preserved as paid-admission-original-96.json before the final resource-qualified admission is bound in execution-start.json. Parent denominators remain96/12; report eligible and excluded counts separately. Both memory and ordinary recovery rights remain unchanged. USD3.00 and600-call upper limits remain hard caps, not a target to spend. All first responses and stop conditions stay in force.

This is an adaptive preparation correction before model outcomes, not an untouched preregistration from the beginning. It cannot support claims about superiority under arbitrary input budgets. Larger-input deployment needs a separate fixed protocol rather than pretending an unrun source was solved.
