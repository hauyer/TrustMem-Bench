# Executable development protocol, version 0.2

This release builds an agent environment; it does not establish a new method or benchmark novelty. All legacy inputs remain development materials. Freeze this protocol and the implementation before interpreting any run.

## Questions

1. Can an external process acquire, retain, and later cite the observations required by a changed task?
2. Does independent numeric scoring distinguish correct answers, supported declarations, unsupported lucky answers, abstention, and process/format failure?
3. Can ordinary exact calculators and eager/lazy caches close the controlled tasks? Their success is retained as a required reference, not treated as an author-method failure to hide.

## Initial admission and controls

Three deterministic engineering streams instantiate nonnegative joint counts, numeric thresholds, and signed interval sums. Each has eight requests with sufficient-history controls, an insufficient observation, a repeat after actual persistence, a changed source, a repeat after repair, another group, and a return to an older source. They are engineering fixtures, not natural histories, held-out data, or independent statistical replications.

The next development replay may use the already acquired GH Archive and Wikimedia snapshots. Use the first source's marginal ranks for query selection; do not select tasks on joint answers or method wins. Admit both source versions with SHA256 bindings. These are two additional source streams sharing the joint-count task mechanism; they do not constitute two new reasoning mechanisms.

## Common abilities

Each policy receives the same domain rules, initial history, trusted current source identity, query and exact-calculation tools, and persistent-observation API. No formula, boolean or action label is individually precomputed and inserted into a policy observation. The shared calculator may derive sufficiency when explicitly called and is an ordinary baseline capability, not a novel contribution.

All policies pay for an actual common initial source scan. At bootstrap the full table from that scan can be retained before future tasks are revealed; this permits the strong early-materialization reference without charging it an artificial second history scan. Later scans, storage, agent transport, startup and scoring are recorded separately. Group scans may stop early only with previously certified contiguous source layout. Source bytes are actual logical file reads, including compressed read-ahead, not network billing or disk I/O. No artificial delays or hard memory restriction are used in the initial pilot.

Policies: always_verify, lazy_group, lazy_full, eager_full. The last three share the same public calculator and legal history access. The policy is a fresh subprocess on every invocation. Query observations are transient until explicitly saved to SQLite. Memory is reopened at each task. Task streams and scoring answers remain controller-only. Submit commits the supplied integer even when it is wrong or unsupported; there is no hidden host repair or safety gate. Cite coverage is declarative, not proof that a model causally used a specific fact.

The subprocess interface assumes a cooperating adapter. It is not an operating-system sandbox: a local program retains host filesystem permissions and must not inspect case manifests, source files outside tools, earlier grading outputs, or use out-of-band persistent state. Hidden-stream and controlled-memory claims are scoped to the JSON interface and audited cooperating adapters. Untrusted-agent evaluation requires a separately isolated deployment. No such isolation is claimed in this development release.

## Scoring and limits

Numeric reference answers are computed after the entire stream, by a separate raw-data parser and SQLite aggregation. Evidence coverage follows a public deterministic contract with independent boundary/mutation tests; it is not an independent semantic annotator. Every attempt remains in the denominator. Never pool the old 31 catalog records with new execution opportunities. Within-stream repeated requests are correlated; report paired stream results and source/mechanism grouping, with no population claim from this pilot.

Initial engineering budget: zero external model calls, USD 0. Native replay budget: zero external model calls, USD 0, using already downloaded files. Model work requires a separately frozen input/call/token/USD limit and an adapter ledger. The runner itself does not meter or authorize paid services. No retries for better outputs; errors and recovery versions remain visible.

## Release gates

An installable runner, real observations and persistence, independent numerical references, ordinary baselines, and complete traces are engineering gates. Top-venue scientific readiness additionally needs an independently verified evaluation gap, diverse native workflows, frozen held-out histories, model/system comparisons, human or independent semantic calibration, cost qualifications, clear licenses, and evidence-backed findings. These gates remain open and cannot be passed by adding a runtime alone.
